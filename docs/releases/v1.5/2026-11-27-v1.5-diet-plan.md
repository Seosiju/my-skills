# my-skills v1.5.0 다이어트 및 병렬 오케스트레이션 계획

작성일: 2026-11-27  
목표 버전: `v1.5.0` (`v1.4.2`의 `stable` 업데이트 채널이 `v1.*`을 추적하므로, 기존 설치본에서 `my-skills update`로 바로 업그레이드 가능)

---

## 1. 목적과 핵심 원칙

`my-skills`의 본질은 단순하다.

> **하나의 스킬 저장소(`my-skills.toml` + `skills/`)를 Git으로 여러 PC(macOS·Windows)에 공유하고, Claude Code·Codex·Antigravity CLI(`agy`)가 따로 놀지 않고 함께 쓰게 한다.**

빠른 Rust 재작성과 기능 추가를 거치며 명령어 21개, 전체 약 34,000줄 규모로 비대해졌다. `v1.5.0`은 다음 원칙으로 표면적과 내부 군살을 동시에 줄인다.

1. **연결은 `sync` 하나로 통일한다.** `my-skills.toml`(+ `my-skills.local.toml`)이 정답이며, `sync`가 생성·갱신·제거(prune)뿐 아니라 설정이 바뀐 `link`↔`copy` 전환까지 처리한다.
2. **기존 사용자 데이터와 자동화는 깨지 않는다.** 기존 `my-skills.toml`, `my-skills.local.toml`, `state.json`(schema v1), git hook 5종, `my-skills update` 경로는 100% 호환을 유지한다.
3. **실사용 안전밸브는 남긴다.** Windows `agy`의 `copy` 모드처럼 복사본 드리프트(`DRIFTED`/`CONFLICT`)를 진단할 때 필요한 `diff`는 유지한다.
4. **옛 Python v0.4 호환 잔재와 중복 테스트를 걷어낸다.**

## 3. 명령어 정리 (21개 → 15개)

### 유지하는 15개 명령어
| 묶음 | 명령어 | 역할 |
|---|---|---|
| 처음·PC 세팅 (4) | `init-registry` | 새 스킬 저장소 생성 (기본 시드 3종 + git + 훅 5종) |
| | `bootstrap` | 새 PC에서 `git clone` 후 한 번에 연결(`sync`) + 훅 설치 (`--skip-tool-install` 제거) |
| | `set-root` | 기본 활성 레지스트리 경로 지정 |
| | `update` | `my-skills` 바이너리 자가 업데이트 |
| 연결 맞추기 (1) | `sync` | `my-skills.toml` 대로 생성·갱신·제거(prune) + 설정 변경 시 자동 `link`↔`copy` 전환 |
| 스킬 관리 (4) | `new` | 새 스킬 초안(`skills/<name>/SKILL.md`) 생성 및 비활성 등록 |
| | `import` | 외부 폴더(`import <path>`) 및 호스트 로컬 스킬 회수(`import --from <host> [<name> \| --plan]`) 통합 |
| | `enable` | 매니페스트에서 스킬 활성화 |
| | `disable` | 매니페스트에서 스킬 비활성화 |
| 조회·검사 (4) | `skills` | 스킬 목록 + 에이전트별 연결 상태·원본 경로 조회 (`--with-governance` 제거) |
| | `validate` | `SKILL.md` 형식 및 호스트별 실측 표시 경고 검사 |
| | `diff` | 호스트 복사본과 정본의 차이 및 `--patch` 확인 (Windows `copy` 모드 드리프트 진단용 유지) |
| | `doctor` | PC 환경·활성 저장소·호스트별 연결 수·git 훅 건강 진단 (구 Python 잔재 정리) |
| 보조·자동화 (2) | `hooks` | git 훅 설치·제거·상태·내부 실행(`hooks run`) |
| | `data-path` | Git 밖에 보관할 스킬별 비밀/로컬 설정 폴더 경로 출력 |

### 제거·통합하는 6개 명령어
- `install` → `sync`로 통합 (제거 없이 연결만 필요하면 `sync --no-prune`)
- `uninstall` → 제거 (스킬 제외는 `disable` + `sync`가 정석)
- `convert` → `sync`로 통합 (`my-skills.toml` 또는 `my-skills.local.toml`에서 `install_mode` 변경 후 `sync`로 안전 전환; 로컬 수정된 `DRIFTED` 복사본은 기존처럼 차단)
- `status` → `skills`로 통합 (`skills`가 이미 에이전트별 연결 상태를 포함)
- `share` → `import --from <host>`로 통합
- `resolve` → 제거 (`skills <name> --json`이 `canonical_path` 제공, `link` 호스트는 파일 자체가 정본)

## 5. 모듈 의존성 구조

위에서 아래로만 참조하는 단방향 레이어 구조를 유지한다.

```text
[Layer 4] 진입점        main.rs ─▶ cli.rs (15개 명령 정의)
                                      │
[Layer 3] 입출력 조합   commands/* ───┴──▶ 도메인 결과를 출력·종료코드(0/1/2)로만 변환
                           │
        ┌──────────────────┼──────────────────────┐
        ▼                  ▼                      ▼
[Layer 2] 도메인        registry/*             drive/{plan,apply,diff}   git/hooks.rs
                     (root,edit,seeds,       (연결 계획·원자적 적용·비교)  (5종 훅)
                      import,catalog)             │
                           │    └────────┐        │
                           ▼             ▼        ▼
[Layer 1] 코어 모델     registry/manifest.rs   drive/{hosts,state,link,hash,lock,ignore}
                        check/{frontmatter,validate} ──▶ drive/hosts (실측 상수만 참조)
                        update.rs
                           │
                           ▼
[Layer 0] 기반          platform/{paths,data}.rs, error.rs
```

- `registry/manifest.rs`를 순수 데이터 모델 계층으로 유지해 `registry`와 `drive` 간 모듈 순환 의존을 방지한다.
- `check/`는 `drive/hosts.rs`의 정적 실측 상수만 참조하여 다른 도메인과 완전히 분리된다.
- 외부 크레이트(`Cargo.toml`): `clap`, `serde`/`serde_json`/`toml`, `yaml-rust2`, `pulldown-cmark`, `similar`(`diff --patch`), `sha2`/`walkdir`, `cap-std`/`cap-fs-ext`(안전한 import), `fs4`/`tempfile`, `junction`, `ureq`/`flate2`/`tar`/`zip`/`semver`/`url`, `include_dir`, `dirs`, `anyhow`, `thiserror`.

## 6. 병렬 오케스트레이션 및 워커 배치 계획

### 역할 분담 원칙
- **오케스트레이터 (`agy`, `gemini-4-neon`, XHigh):** 구현 코드를 직접 쓰지 않는다. 기준선 기록 → SPEC 짝 표 작성 → 계약 커밋 → worktree·brief 생성 및 배포 → diff 검수 및 커밋 → 통합 병합 → 격리 빌드/테스트 및 `hub-check.py` 실행 → 최종 문서·릴리스를 전담한다.
- **교차 계열 블라인드 리뷰:** 모든 구현 스트림은 코드를 작성한 모델과 **다른 계열**이 `SPEC.md`와 `git diff`만 보고 리뷰한다(brief·워커 보고서 열람 금지). 수정은 원 워커가 맡고 재리뷰 후 통합한다.
- **안전·자원 규칙:**
  - 자동 승인 플래그(`--yolo`, `--dangerously-skip-permissions`)를 쓰지 않는다. Codex는 `--approve-for-me`로 띄우고 오케스트레이터가 커밋한다. `agy`는 기본 Auto 모드로 띄운다.
  - 메모리·MSVC `LNK1104` 방지를 위해 `cargo` 빌드는 동시 **최대 2개**(`-j 2`)까지만 실행한다.
  - 모든 테스트·빌드는 격리 디렉터리(`HOME`, `USERPROFILE`, `LOCALAPPDATA`, `XDG_*`, `CARGO_TARGET_DIR`)에서 실행해 실제 사용자 레지스트리와 호스트 폴더를 건드리지 않는다.
